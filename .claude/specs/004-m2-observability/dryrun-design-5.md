### Pass 3 — Interface Contract Validation: CLEAN

All boundaries explicitly defined:
- **Sink Protocol** (`sinks/base.py`): `put(record: dict) -> None` + `shutdown() -> None` — both required. Duck-typing contract enforced at registration ✓
- **SinkRegistry**: `publish(subject, record)` + `register(subject, sink)` ✓
- **record_phase()**: context manager API; sole injection point; no import from sinks/registry ✓
- **WsBridgeSink.shutdown()**: NOW concretely specified as SYNC — dedicated event loop thread; `asyncio.run_coroutine_threadsafe(_do_shutdown(), self._loop).result(timeout=2.0)`; guard for closed loop; loop.stop() + thread.join() in finally block ✓. No async/sync ambiguity remains.
- **FileSink.shutdown()**: sentinel enqueue + `join(timeout=5.0)` ✓
- **TuiSink.shutdown()**: `_stop_event` set + `join(timeout=2.0)` ✓
- Processor-to-registry injection: constructor injection, no singleton/service-locator ✓

### Pass 4 — State Machine & Transitions: CLEAN

- **ObservabilityFaculty**: `threading.Event _shutdown_called` — set-before-proceed idempotency; all transitions safe ✓
- **FileSinkDrainer**: pure poison-pill; one exit mechanism (sentinel); no competing stop-event ✓
- **WsBridgeSink**: `__init__()` → loop created + thread started → server coroutine scheduled → `shutdown()` → run_coroutine_threadsafe → cancel/await → loop.stop() → thread.join() ✓. `self._loop is None or self._loop.is_closed()` guard covers the never-started or double-shutdown case ✓
- Shutdown ordering: OTel force_flush/shutdown → sinks in reverse registration order (WsBridgeSink → TuiSink → FileSink). Live sinks stopped first, file sink flushed last ✓

### Pass 5 — Failure Path Analysis: CLEAN

- FileSink file-open failure → `RuntimeError` at `__init__()` → composition root fails fast; no silent loss ✓
- FileSinkDrainer `doRollover()` IOError/OSError → logged to stderr, drainer continues writing to pre-rotation file ✓
- WsBridgeSink `shutdown()` timeout (2s) → logged to stdlib, finally block still calls loop.stop() + thread.join() ✓
- WsBridgeSink `shutdown()` generic exception → logged, not propagated to caller ✓
- Sink `put()` raises → logged, next sink still receives record (AC-11.3) ✓
- Processor serialization error → logged to stdlib, not published to bus (AC-11.4) ✓
- Client disconnect / WS send error → logged, not on bus (AC-08.5) ✓

### Pass 6 — Concurrency & Ordering: CLEAN

- TuiSink: `threading.Lock _deque_lock` guards compound check-then-mutate (drop-oldest + gap_marker + append) — atomic with respect to drain task ✓
- WsBridgeSink: per-client `threading.Lock` — same compound-atomicity rationale ✓
- FileSink: `queue.Queue` is thread-safe; put_nowait() + get() are individually atomic ✓
- WsBridgeSink drain task acquires per-client lock before popleft() — no race with put() ✓
- Post-shutdown put() race: explicitly and completely addressed in §2.5 — "no guard by design"; the shutdown ordering invariant (OTel processors flushed before any sink.shutdown()) makes the race structurally impossible under correct composition; this is documented as an API contract, not a silent gap ✓
- Single producer → no publisher-side concurrency issue; SinkRegistry.publish() called only from OTel processor callbacks ✓

### Pass 7 — Edge Cases & Boundaries: CLEAN

- First run / cold start: `trace_dir.mkdir(parents=True, exist_ok=True)` before FileSink construction ✓
- Age-based rotation concurrency: **explicitly scoped** as single-process only (M2); multi-process access to `~/.axiom/traces/` is an explicit M3+ constraint ✓
- WsBridgeSink never-started / double-shutdown: `self._loop is None or self._loop.is_closed()` guard ✓
- WsBridgeSink with no connected clients: `_server_task.cancel()` is safe on a server task with zero clients; CancelledError caught ✓
- WsBridgeSink `_do_shutdown()` with None `_server_task` (server never started): guarded by `if self._server_task is not None` ✓
- File rotation: permissions re-applied to new file after `doRollover()` (`os.chmod(handler.baseFilename, 0o600)`) ✓
- Sink registration with no optional sinks (no TUI, no WS): only FileSink registered; publish() iterates empty list for absent subjects, no error ✓
